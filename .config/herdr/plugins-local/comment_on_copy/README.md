# comment_on_copy

복사한 터미널 텍스트에 코멘트를 달아 에이전트 입력창에 꽂는다.

이름 그대로 트리거는 복사다. herdr의 `copy_on_select`와 짝을 이룬다고 보면 된다.
드래그는 복사를 일으키는 여러 방법 중 하나일 뿐이고, 더블클릭으로 단어를 집거나
copy mode에서 키보드로 범위를 잡아 복사해도 똑같이 창이 뜬다. 마우스 없이 쓸 수 있다.

## 쓰는 법

백틱(prefix) 다음 `i`로 모드를 켠다. 모드가 켜져 있는 동안 무언가를 복사하면
코멘트 창이 뜬다. 코멘트를 쓰고 `^S`를 누르면 아래 형식이 대상 에이전트의
입력창에 들어간다. 제출은 하지 않는다.

```
<context>
workspace: main
tab: 1
pane: wD:pH (nvim)
cwd: ~/Works/socra-ai-web/main
branch: main
selection: 20 lines, 688 chars
file: apps/native/lib/services/observers/system_metrics_observer.dart:29
</context>

<selection>
복사한 텍스트
</selection>

코멘트
```

`context`는 복사 시점에 모은다. 창이 뜬 뒤에 물어보면 이미 달라져 있다. 값이 없는
항목은 넣지 않는다. 에이전트 pane에서 복사하면 `pane`에 에이전트 이름이, 그 세션이
무슨 일을 하고 있었는지가 `title`에 붙는다. 셸이나 편집기 pane이면 그 자리에 돌고
있던 명령이 들어간다.

`file`은 복사한 내용을 `rg`로 저장소에서 찾아 붙인다. 편집기 안에서 복사하면 파일
이름이 어디에도 남지 않기 때문이다. 가장 긴 줄로 검색해 한두 파일로 좁혀질 때만 쓰고,
줄 번호는 선택 범위의 첫 줄로 다시 짚는다. 좁혀지지 않으면 아무것도 붙이지 않는다.
로그나 에러 메시지처럼 파일에 없는 내용은 이 단계에서 자연히 걸러진다.

복사한 내용이 `<selection>` 태그를 품고 있으면 바깥 태그는 `<selection-2>`가 된다.
이 플러그인의 결과물을 다시 복사했을 때 경계가 무너지지 않게 하기 위해서다.

창 안의 키는 이렇다.

| 키 | 동작 |
| --- | --- |
| `^S` | 입력창에 넣는다. 제출은 하지 않는다 |
| `^E` | 넣고 바로 제출한다 |
| `^Y` | 클립보드로 복사한다. 창은 닫히지 않는다 |
| `^L` | 목적지를 바꾼다. 고르면 제목 줄의 `to`가 따라 바뀐다 |
| `PageUp` `PageDown` | selected 영역을 굴린다 |
| `Esc` | 닫기 |

창 제목 줄이 `comment  to  <목적지>` 형태로 현재 목적지를 보여주고, 바로 옆에 목적지를
바꾸는 버튼을 둔다. 목적지가 없으면 에이전트가 하나여도 고를 수 있다. 셸 pane에서
복사하면 목적지가 안 잡히는데 보낼 곳은 있는 경우가 그렇다.

상태줄은 결과를 색으로 구분한다. 성공은 초록, 거절이나 빈 입력은 노랑, 안내는 흐린 회색이다.

두 영역 모두 스크롤한다. 휠은 커서가 올라온 영역을 굴리고, 프레임 오른쪽 테두리가
그대로 스크롤 막대가 된다. 내용이 다 보이면 막대를 그리지 않는다. 코멘트 영역의
스크롤은 키를 누르면 커서를 다시 따라가고, 휠로 굴리는 동안에는 그 자리에 머문다.
커서 줄이 화면 밖으로 나가면 커서를 감춘다.

버튼은 마우스로도 누를 수 있다. 제출 버튼을 `ctrl+클릭`하면 즉시 제출이다.
`shift+클릭`이 아닌 이유는 WezTerm이 shift+마우스를 자기 선택용으로 예약해 앱까지
내려오지 않기 때문이다. 키도 마찬가지로 `ctrl+shift+s`가 `ctrl+s`와 같은 바이트로
와서 구분할 수 없다. 그래서 별도 키를 쓴다.

즉시 제출은 `agent.prompt`를 쓴다. 텍스트와 Enter를 한 덩어리로 보내고, 상대가
승인 프롬프트에서 대기 중이면 herdr가 거절한다. 남의 확인 질문에 코멘트가 답으로
들어가지 않는다.

## 목적지를 정하는 규칙

복사한 자리에서 가까운 순서로 찾는다. 복사가 일어난 pane, 복사 시점의 포커스 pane,
같은 탭, 같은 workspace, 그리고 전체 순이다. 범위마다 후보가 하나일 때만 고른다.
둘 이상이면 비워두고 사람이 `^L`로 고른다. 잘못 고르는 것보다 낫다.

편집기나 셸 pane에서 복사할 때 이 범위가 일한다. 그 pane에는 에이전트가 없지만
대개 같은 탭에 하나 있다.

포커스는 드래그 시점에 기록한다. 팝업이 뜨는 순간 포커스는 팝업으로 넘어가기 때문이다.

이름은 `claude · main`처럼 에이전트 종류와 workspace 이름으로 짓는다. 같은 조합이
둘 이상일 때만 탭 이름이나 pane 번호를 덧붙인다.

## 모드 표시

모드가 켜져 있는 동안 사이드바의 workspace 행에 `comment`가 뜬다. watcher가 5초마다
workspace metadata 토큰을 갱신하고 ttl을 15초로 잡는다. 프로세스가 비정상으로 죽어도
표시가 저절로 사라지므로 상태 파일과 화면이 어긋나지 않는다.

찍을 자리는 `config.toml`의 `[ui.sidebar.spaces]`가 정한다. 탭바 우측
(`tab_bar_right`)은 `hide_tab_bar_when_single_tab`이 켜져 있어 쓸 수 없다.

## 어떻게 동작하나

herdr는 지금 무엇이 선택돼 있는지 알려주는 수단이 없다. 이벤트도 조회도 없고,
플러그인 액션은 키바인딩 경로와 CLI 경로 어느 쪽에서도 `selected_text`를 받지 못한다.
herdr가 선택을 소유하는 셸 pane에서 선택을 유지한 채 확인한 결과다.
그래서 `copy_on_select`가 켜져 있을 때 클립보드에 올라온 내용을 선택한 텍스트로 쓴다.

pane마다 마우스 주인이 다르다는 점이 중요하다. Claude Code pane은 앱이 마우스를 가져가
자기 선택을 그리고 자기가 클립보드에 쓴다. 셸 pane은 herdr가 소유하므로 herdr의
`copy_on_select`가 켜져 있어야 클립보드가 채워진다. 그래서 기본값인 `true`를 유지한다.
`false`로 두면 선택 영역은 모든 pane에서 유지되지만 셸 pane에서는 이 플러그인이
동작하지 않는다.

사람이 복사한 것만 걸러내려고 두 가지를 본다. 하나는 최전면 앱이다. 변화 직전과
변화 시점 모두 터미널이 앞에 있어야 한다. 다른 하나는 값의 재등장이다. 최근 60개
값을 기억해두고 이미 본 값이 다시 올라오면 무시한다. Raycast 같은 클립보드 도구는
히스토리에서 고른 항목을 클립보드에 쓴 뒤 붙여넣는데, 그 항목은 정의상 전에 있던
값이라 여기서 걸린다. 그 도구들은 앱 활성화를 하지 않아 최전면으로는 잡히지 않는다.

watcher가 뜨기 전에 복사했던 오래된 항목을 히스토리에서 꺼내면 처음 보는 값이라
창이 뜬다. 같은 텍스트를 의도적으로 두 번 복사해도 두 번째는 뜨지 않는다.

판단 근거는 `$HERDR_PLUGIN_STATE_DIR/trace.log`에 남는다. 무시한 경우도 이유와 함께
기록하므로 오탐이 의심되면 이 파일을 본다.

`watch.py`가 클립보드를 0.35초마다 확인한다. 내용이 바뀌고 최전면 앱이 WezTerm이면
선택한 텍스트로 보고 팝업을 연다. 좌표는 각 pane의 화면 텍스트에서 그 문자열을 찾아
되짚는다. 표시용이라 같은 문자열이 여러 번 나오면 첫 번째를 고른다.

전송은 소켓의 `pane.send_input`을 쓴다. `pane.send_text`는 개행을 Enter로 보내서
여러 줄이 줄마다 제출된다. `send_input`은 bracketed paste를 지켜 한 덩어리로 들어간다.

## 한계

모드가 켜져 있는 동안에는 붙여넣으려고 한 복사에도 창이 뜬다. 클립보드에는 누가
썼는지에 대한 정보가 없어서 두 경우를 구분할 방법이 없다. 모드 토글이 그 구분을
사람 손에 맡기는 장치다.

팝업은 세션 모달이라 떠 있는 동안 키보드를 가져간다. 드래그한 줄 옆에 붙이는 인라인
배치는 herdr의 plugin pane placement가 좌표를 받지 않아 불가능하다.

watcher는 5초마다 자기 소스의 수정 시각을 확인하고 바뀌었으면 스스로 다시 뜬다.
코멘트 창이 열려 있는 동안에는 건너뛴다. 고칠 때마다 모드를 껐다 켜는 것을 잊어
옛 코드가 도는 일이 반복돼서 넣었다.

창을 띄울 때 tty의 제어 문자 몇 개를 해제한다. macOS는 `^S`를 XOFF로, `^Y`를 DSUSP로
쓰기 때문에 그대로 두면 두 키가 앱까지 오지 않는다. 마우스 클릭은 이 경로를 안 거치므로
버튼만 동작하고 단축키만 안 먹는 증상으로 나타난다. 창을 닫을 때 원래 설정으로 되돌린다.

수정키로 동작을 가르는 것은 터미널에서 잘 되지 않는다. `ctrl+shift+s`는 `ctrl+s`와 같은
바이트로 오고, `shift+클릭`은 WezTerm이 자기 선택용으로 예약해 앱까지 내려오지 않는다.
구분되는 것은 `ctrl+클릭` 하나뿐이라 즉시 제출에 그것을 쓴다.
